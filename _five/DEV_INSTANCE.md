## 1. 获取真实测试地图

1. 确保游戏已退出并正常保存；拒绝复制运行中的存档。
2. 从正式版 `saves/oldworld` 完整复制到 dev 的专用目录，保留原有 dev 世界，不覆盖。
3. 全量校验源与目标的相对路径、大小、SHA-256；复制前后检查源未变化。复制包括主世界/下界/末地、玩家、进度、统计、队伍、领地、载具、模组存储，不只拷 playerdata。
4. 保留不可变基准快照。每次 A/B 从同一快照恢复，不能让后测组复用先测组已生成的新区块。
5. 测试地图的进度永远不回流到正式地图；正式地图与 dev 地图从此独立。

## 2. 在 dev 开发与测试

- 先记录 dev 与正式版的模组、配置、画质和实际 JVM 差异。创建可回滚的 dev 备份，必要时将 dev 运行配置对齐正式版建立基线；保留 dev 自己的版本 id、隔离设置和已有世界。
- 测量只使用白名单测试世界的绝对路径，不按世界显示名判断，不把固定用户名当作唯一玩家。
- 先跑工具自检：路线开始/结束/坐标、探针结果、正确世界路径及脚本无错误缺一不可；失败轮作废，不能进入结果表。
- 正式对照：开/关 irisflw，分别采集静止、首次新区块、已有区块。恢复一致世界快照，交替顺序，每组至少三次。冷启动和预热后分开看。
- 衡量平均 FPS、1% low、长帧数量与总时长、最长帧；同时记录 JFR/GC/tick。高 FPS 但更多冻结不能算单纯成功。
- 不降低当前画质、分辨率、光影、材质、视距与模拟精度。不漏画、不闪实体、不减少可见机械更新冒充优化。
- 所有改变 mod 行为的代码登记到 `_five/MOD_PATCHES.md`；试验性采样工具只供 dev 使用，不打进发布包。

## 3. 成熟后发布新版正式包（需用户确认）

1. 发布门槛：重复测量可复现收益；普通 PCL 启动、机械、载具、季节、枪械与好友联机回归通过；截图无画质/渲染回退。
2. 冻结 release 清单：精确模组版本、配置、覆盖文件、补丁登记、哈希及已知问题。
3. 创建新的正式版本/发布包，不原地覆盖当前正式版。排除测试探针、JFR、日志、账号令牌、开发地图和个人存档。
4. 输出朋友更新说明，区分客户端可选渲染模组和两端必须一致的内容/网络模组；不能只凭依赖 side 字段承诺任意组合兼容。
5. 验证安装到空目录可启动，随后执行正式存档迁移。

## 4. 正式地图迁移（不是把 dev 测试地图转正）

1. 发布时停止联机并退出旧正式版；备份当时最新的完整正式存档及旧版运行配置。
2. 把**旧正式版此刻最新的地图**完整复制进新正式版，绝不拿早先 dev 测试副本覆盖最新进度。
3. 保持朋友的账号/游戏名、认证模式、UUID Fix/映射设置一致。复制所有世界数据可最大程度保留背包、末影箱、进度、任务、领地、载具；仍须核验具体模组是否另有实例级外部数据需要随迁。
4. 检查出生位置、背包、末影箱、任务/队伍/领地、机器与载具，并让朋友实际进入验证。
5. 旧正式版和旧存档备份保留不删；若新版本改变数据格式，不能直接把升级后存档降级回旧版。回滚使用升级前备份，并明确升级后新增进度可能无法保留。
